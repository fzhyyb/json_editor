# 裸转义 JSON 自动识别设计

## 目标

让编辑器识别缺少最外层字符串引号、但内部仍保留 JSON 字符串转义的对象或数组，例如：

```text
{\"mode\":\"A\",\"pass\":true}
```

粘贴或从 uTools 文本入口进入后，应用应自动还原为合法 JSON，继续执行现有递归展开与两空格格式化。点击“递归解析”和“去转义”时也应采用同一识别规则。

## 识别边界

标准 JSON 和标准 JSON 字符串始终优先按现有逻辑解析。只有严格解析失败时才尝试裸转义兜底。

裸转义候选必须同时满足：

- 去除首尾空白后以 `{` 开头并以 `}` 结尾，或以 `[` 开头并以 `]` 结尾；
- 内容补齐最外层字符串引号后能够被 `JSON.parse` 解码一次；
- 解码结果能够被现有 JSON 解析器解析为对象或数组。

任何一步失败都视为无效输入，不执行全局 `\"` 替换，不修改编辑器中的原文。

## 组件与数据流

在 JSON 解析模块中新增一个小型标准化函数，职责仅为把裸转义容器还原为普通 JSON 文本。它不负责格式化和递归遍历。

现有入口按以下顺序工作：

1. 尝试现有标准 JSON / JSON 字符串解析。
2. 标准解析失败时调用裸转义标准化函数。
3. 标准化成功后重新进入现有递归解析流程。
4. 输出仍由现有序列化器以两空格格式化，并将光标定位到首行。

“去转义”操作仍然只移除一层转义。对于标准 JSON 字符串沿用原行为；对于裸转义容器，返回标准化后的普通 JSON 文本。

## 错误处理

- 标准 JSON 行为不得变化。
- 不是对象或数组的裸转义文本不接受。
- 部分转义、缺少闭合括号、包含未转义引号或解码后仍非合法 JSON 时，保留原文并显示现有错误状态。
- 自动粘贴失败保持静默回退，让 CodeMirror 完成普通粘贴；手动操作失败继续显示错误。

## 测试

新增回归测试覆盖：

- 用户提供的对象结构能够解除一层裸转义；
- 裸转义数组能够解析；
- 粘贴、uTools 文本入口、递归解析和“去转义”入口行为一致；
- 标准 JSON 字符串行为保持不变；
- 普通 JSON 对象不会被“去转义”误处理；
- 截断结构、普通反斜杠文本和无法二次解析的输入保持失败且原文不变。

## 非目标

- 不尝试修复从大型 JSON 中间截取的残缺片段。
- 不对任意文本执行全局反斜杠替换。
- 不改变压缩、格式化、搜索和折叠功能。
