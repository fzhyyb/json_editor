# uTools 递归 JSON 解构插件设计

日期：2026-08-11

## 1. 目标

开发一款可发布到 uTools 应用市场的插件。用户提供标准 JSON 或 JSON 字符串后，插件递归识别其中被字符串化、转义的 JSON 对象和数组，将其逐层还原为真正的对象或数组，格式化展示并复制结果。

示例输入：

```json
{
  "data": "{\"user\":{\"name\":\"小明\"},\"items\":\"[1,2,3]\"}"
}
```

示例输出：

```json
{
  "data": {
    "user": {
      "name": "小明"
    },
    "items": [
      1,
      2,
      3
    ]
  }
}
```

## 2. 范围

首版包含：

- uTools 功能指令打开插件。
- 复制文本后通过 uTools 文本匹配入口打开并自动处理。
- 手工粘贴、编辑和重新处理。
- 严格 JSON 解析。
- 对对象、数组及其中的嵌套字符串进行递归展开。
- 左右对照展示原文与结果。
- 成功后自动复制结果，并允许再次手动复制。
- 外层错误、嵌套错误路径和深度警告。
- 深浅主题适配及常用键盘快捷键。
- 自动化测试、离线测试包准备和应用市场发布素材。

首版不包含：

- JSON5、JavaScript 对象字面量、注释、单引号或尾逗号解析。
- JSONPath 查询、字段搜索、历史记录或云同步。
- 将字符串形式的数字、布尔值和 `null` 转为原始类型。
- 网络请求、账号、付费能力或数据上报。

## 3. 用户流程

### 3.1 一键入口

1. 用户在任意应用复制 JSON 文本。
2. 用户呼出 uTools，并选择“递归解构 JSON”。
3. uTools 通过 `onPluginEnter` 把匹配文本交给插件。
4. 插件自动解析、递归展开、格式化并复制。
5. 界面显示原文、结果、展开字段数及复制状态。

### 3.2 编辑入口

1. 用户通过“JSON 解构”等功能指令打开插件。
2. 用户在左侧粘贴或编辑 JSON。
3. 用户点击“解构并复制”或使用执行快捷键。
4. 插件在右侧展示结果并自动复制。

## 4. 解析语义

### 4.1 外层解析

- 输入必须能被 `JSON.parse` 解析。
- 若解析结果本身是字符串，则仅当去除首尾空白后以 `{` 或 `[` 开头时继续尝试解析，直至获得对象或数组，或无法继续解析。
- 最终顶层结果必须是对象或数组；否则报告输入不是 JSON 对象或数组。
- 外层解析失败时不更新结果区，也不覆盖剪贴板。

### 4.2 递归展开

对每个对象字段和数组元素执行以下规则：

1. 对象和数组继续遍历其子元素。
2. 对字符串先去除首尾空白，仅当其以 `{` 或 `[` 开头时尝试 `JSON.parse`。
3. 只有解析结果为对象或数组（包括空对象和空数组）时，才替换原字符串；`null` 不替换。
4. 替换后继续遍历新值，从而处理任意多层转义。
5. 数字、布尔值、`null` 和普通字符串保持不变。
6. 属性遍历顺序保持与解析所得对象一致，不主动排序。

### 4.3 限制与诊断

- 最大递归展开深度为 100 层，顶层对象或数组记为第 0 层。
- 达到上限时保留尚未处理的值，并记录警告路径。
- 疑似 JSON 的嵌套字符串解析失败时保留原字符串，并记录其 JSONPath 风格路径，例如 `$.data.payload` 或 `$.items[2]`。
- 处理结果包含：展开后的值、成功展开计数、未展开警告列表和是否触达深度上限。

## 5. 界面设计

采用经用户确认的“左右对照”布局：

- 顶栏：插件名称、当前状态和主操作按钮。
- 左栏：可编辑的“原始 JSON”。
- 右栏：只读的“解构结果”，以 2 个空格格式化。
- 状态区：显示“已展开 N 个字段、已复制”、无可展开字段提示或错误摘要。
- 警告区：列出无法展开的嵌套路径，避免静默忽略。
- 辅助操作：复制结果、清空、重新处理。

窗口变窄时，左右两栏改为上下排列。界面跟随系统深浅主题，不依赖远程字体、图标或其他网络资源。

快捷键：

- macOS：`Command+Enter` 执行，`Command+Shift+C` 复制结果。
- Windows/Linux：`Ctrl+Enter` 执行，`Ctrl+Shift+C` 复制结果。

## 6. 工程设计

采用零运行时依赖的原生 HTML、CSS 和 JavaScript，不使用构建步骤。

```text
plugin.json
index.html
styles.css
assets/
  logo.png
src/
  json-unwrapper.js
  utools-adapter.js
  app.js
tests/
  json-unwrapper.test.js
README.md
docs/
  marketplace.md
  privacy.md
```

模块职责：

- `json-unwrapper.js`：纯解析逻辑，输入字符串并返回结构化结果或明确错误；不访问 DOM、剪贴板或 uTools。
- `utools-adapter.js`：封装 `onPluginEnter`、`copyText` 和运行环境判断；在普通浏览器预览时提供安全降级。
- `app.js`：维护输入、结果、状态与警告，连接界面事件和适配层。
- `plugin.json`：配置 HTML 入口、Logo、功能指令和任意文本匹配指令。首版不需要 `preload.js`。

## 7. 错误处理

- 外层 JSON 无效：左栏显示解析信息，右栏保留上一份有效结果，剪贴板不变。
- 顶层不是对象或数组：显示用途提示，不执行复制。
- 嵌套疑似 JSON 无效：继续处理其他字段，保留该字符串并显示路径警告。
- 未发现嵌套 JSON：仍格式化和复制合法输入，提示“未发现可展开的嵌套 JSON 字符串”。
- 剪贴板 API 不可用或复制失败：结果仍正常展示，提示用户手动复制。
- 超过深度限制：返回已安全处理的部分结果，并明确标出截断路径。

## 8. 测试策略

使用 Node.js 内置测试运行器测试纯解析模块，不引入第三方测试依赖。测试至少覆盖：

- 普通对象、数组和嵌套组合。
- 单层、多层、顶层字符串化 JSON。
- 数组中的字符串化对象或数组。
- 字符串形式的数字、布尔值和 `null` 不转换。
- 无效外层 JSON 不产生结果。
- 无效嵌套 JSON 保留原值并返回准确路径。
- 空对象、空数组、中文、Emoji、反斜杠和换行转义。
- 展开计数、属性顺序和类型保持。
- 100 层安全上限。

浏览器级验证覆盖：指令进入、自动处理、自动复制、手工编辑、快捷键、响应式布局及深浅主题。发布前在 uTools 开发者工具中分别完成 macOS 和 Windows 的基本冒烟测试；若无法取得其中一个平台，则在发布说明中明确已验证平台。

## 9. 隐私与安全

- 所有解析均在本地完成。
- 不上传、存储或记录用户输入。
- 不发起网络请求。
- 不使用 `preload.js` 或 Node.js 文件系统权限。
- 自动复制仅在用户显式进入该功能或点击处理按钮后发生。

## 10. 发布交付

交付内容包括：

- 可直接由 uTools 开发者工具接入的源码目录。
- 通过测试的版本与测试记录。
- 供本地验收使用的 UPXS 离线安装包；该文件需在 uTools 开发者工具中生成。
- 应用市场所需的名称、简介、版本说明、用户手册、隐私说明、Logo 和截图方案。
- 发布检查清单与审核提交步骤。

正式上线流程由插件所有者登录 uTools 开发者工具，确认版本目录和版本号，填写应用信息、版本说明与截图后提交审核。审核通过后插件才进入应用市场。

## 11. 验收标准

- 给定合法输入，所有可解析为对象或数组的嵌套 JSON 字符串均被逐层展开。
- 普通字符串和字符串形式的原始值不被误转换。
- 成功结果以 2 空格格式化、在界面可核对并自动复制。
- 任一嵌套错误不会阻止其他字段处理，且能给出准确路径。
- 外层错误不会覆盖用户现有剪贴板内容。
- 核心自动化测试全部通过，uTools 中的两种输入入口均可用。
- 发布目录无远程依赖或不必要权限，并具备完整市场素材与操作说明。
