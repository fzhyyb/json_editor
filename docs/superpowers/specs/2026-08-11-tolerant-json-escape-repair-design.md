# JSON 兼容解析与交互调整设计

## 背景

部分业务数据整体符合 JSON 结构，但字符串值中的 URL 使用了 `\&`。`\&` 不是标准 JSON 转义，因此当前实现会在解析外层 JSON 时直接失败，无法继续展开 `form_card`、`nodes_json` 等字符串化 JSON 字段。

## 目标

- 保持标准 JSON 的现有解析行为不变。
- 对字符串内部的非法单字符转义提供安全、可预期的兼容解析。
- 修复后继续执行现有的递归 JSON 解构。
- 不掩盖缺少引号、括号不匹配等真正的 JSON 结构错误。
- 将“解析”和“复制”改为两个互不隐式触发的操作。
- 不限制用户在界面输入或通过 uTools 文本匹配入口传入的 JSON 字符长度。

## 方案

解析过程采用“严格优先、兼容回退”策略：

1. 首先直接调用 `JSON.parse`。
2. 仅当严格解析失败时，扫描原始文本并识别 JSON 字符串边界。
3. 在字符串内部遇到 JSON 不支持的 `\X` 时移除反斜杠，保留字符 `X`。
4. 合法转义 `\"`、`\\`、`\/`、`\b`、`\f`、`\n`、`\r`、`\t`、`\uXXXX` 原样保留。
5. 对修复后的文本再次调用 `JSON.parse`。若仍失败，沿用现有 `INVALID_OUTER_JSON` 错误。

同一兼容解析函数同时用于外层 JSON、外层字符串化 JSON 和递归字段，确保任意层级的 `\&` 都可以被处理。普通文本字段不会被单独扫描或改写；只有被判定为 JSON 容器候选的字符串才会尝试递归解析。

## 交互设计

- 主按钮文案改为“解析”。点击后只解析并展示结果，不写入剪贴板。
- “复制结果”按钮独立保留，只有在存在成功解析的结果时可用；点击后才写入剪贴板。
- `Command/Ctrl+Enter` 只执行解析，`Command/Ctrl+Shift+C` 只复制已有结果。
- 通过 uTools 文本匹配指令进入时自动填充并解析，但不自动复制。
- 解析成功状态只报告展开数量和警告数量；复制状态只由用户点击复制按钮后报告。
- 解析失败时继续保留上一份有效结果及其复制能力，沿用现有行为。

## 长度策略

- `<textarea>` 不设置 `maxlength`，解析函数也不增加字符数检查。
- uTools `over` 匹配指令的 `maxLength` 是可选字段，但省略后默认最多匹配 10,000 字符，因此不能通过删除字段实现“不限长度”。
- 将 `maxLength` 设置为 JavaScript 最大安全整数 `9007199254740991`，在实际输入范围内等同不限制，同时保留复制文本后直接唤起插件的能力。
- 递归深度上限仍保持 100 层。该限制用于避免极端嵌套造成资源问题，与输入字符长度无关。

参考：[uTools plugin.json 核心配置](https://www.u-tools.cn/docs/developer/information/plugin-json.html)

## 安全边界

- 不使用 `eval` 或动态代码执行。
- 不全局替换反斜杠，只处理 JSON 字符串内部的非法转义。
- 严格解析成功时不做任何修复。
- 修复不会补齐引号、逗号或括号，结构损坏仍然报错。
- Windows 路径等本就不符合标准 JSON 的 `\X` 会按宽松 JSON 的常见语义变成 `X`；若用户需要保留反斜杠，应输入合法的 `\\X`。

## 测试与验收

- 真实问题的最小样例 `{"url":"a\&b"}` 能解析为 `{ "url": "a&b" }`。
- 非法转义位于字符串化 JSON 字段时，也能在递归解构后正确修复。
- 合法转义、Unicode、普通反斜杠和现有递归行为保持不变。
- 括号或语法结构错误仍返回 `INVALID_OUTER_JSON`。
- 使用用户提供的完整输入进行回归，外层成功解析，`form_card` 和 `nodes_json` 被展开，且无未完成解析警告。
- 另外两个用户样例也应完成递归展开且无警告；预期结果与已交付的三份解析结果一致。
- 点击“解析”以及从 uTools 文本入口进入均不会调用剪贴板 API。
- 只有点击“复制结果”或使用复制快捷键才会调用剪贴板 API。
- 清单中的 `maxLength` 为 `9007199254740991`，发布构建保留该值。
- 完整测试套件通过，并重新生成本地 `release/utools-json-unwrapper` 目录。
